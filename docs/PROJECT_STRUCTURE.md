# Portfolio structure

Where things live in this repository and where a new change should go.

## Ownership

- `src/app` owns URLs, route metadata and Next.js entry points. Route files stay thin: they set
  metadata and render a feature. API routes only re-export a handler from its feature folder.
- `src/features/home` owns Home: `hero.tsx`, the About text in `home-page.tsx`, `life-strip.tsx`
  and `portrait.ts`. Home also shows the resume, a few featured projects and the contact section.
- `src/features/resume` owns the resume. Edit content in `resume-data.ts`. `skill-usage.ts` works
  out which jobs and projects used each skill.
- `src/features/contact` owns the contact form. `contact-message.ts` holds the validation rules
  used by both the form and the server; `contact-handler.ts` is the `/api/contact` route.
- `src/features/notifications` is the code shared by the routes that email me (contact and journal
  reactions): the Resend call, the request checks and the rate limiter.
  See [CONTACT_AND_REACTIONS.md](CONTACT_AND_REACTIONS.md).
- `src/features/music` owns the background music player. `music-player.tsx` is mounted in the root
  layout so a song keeps playing across pages. `playlist-tracks.ts` is generated by
  `scripts/refresh-playlist.mjs`; do not edit it by hand.
- `src/features/projects/projects.ts` is the list of projects, in display order. Home features the
  first four; `/projects` lists them all (`project-index.tsx`). `project-page.tsx` is the shared
  page layout for projects without a page of their own.
- `src/features/projects/elsewhere` owns the photo journal. `journal-data.ts` lists chapters,
  photos (with their real pixel size, so nothing is cropped, and alt text) and quotes.
  `journal-layout.ts` decides photo numbering and sides. `photo-viewer.tsx` is the full-size view,
  `shot-actions.tsx` and `use-reactions.ts` are the like/comment/share row, and `reaction.ts` plus
  `reactions-handler.ts` are the `/api/elsewhere/reactions` route.
- `src/features/projects/zempled` owns the listening collection. `sample-pairs.ts` is the data
  (one documented source per pair), `artists.ts` the short artist backgrounds, `pair-order.ts` the
  previous/next/shuffle/index logic, `use-preview-player.ts` the two preview players, and
  `preview.ts` the `/api/zempled/preview` route. See [ZEMPLED_LISTENING.md](ZEMPLED_LISTENING.md).
- `src/features/projects/trace` owns the Trace page, which types out real terminal output saved
  in `recorded-runs.ts`. The tool itself lives in its own repository.
- `src/components` holds code shared across features:
  - `layout`: header and menu, search (`search.ts` is the matching logic), side buttons, footer,
    the curtain page transition (`SiteLink` in `page-curtain.tsx`), arrival screen.
  - `motion`: pointer and scroll effects. `pointer-motion.ts` runs one animation loop for all of
    them. Every effect checks `prefersReducedMotion()`.
  - `culture`: Ge'ez letters (`fidel.ts`, `glyph-layer.tsx`), the tibeb band, and the hover
    "learn" cards with their texts and sources in `lessons.ts`.
  - `providers`, `security` (the Content Security Policy), and `ui`.
- `src/proxy.ts` gives every HTML response a fresh script nonce and the Content Security Policy.
  Keep HTML dynamic and uncached when changing it.
- `src/styles/globals.css` has the colors for light and dark mode; `site.css` has the layout
  classes shared by all pages (`section`, `page-top`, `display-heading`, `pill`, ...).
  Anything specific to one feature goes in a CSS module beside it.
- `public/projects/<slug>` holds a project's images. Portraits and company marks are in
  `public/images`, the resume PDF in `public/documents`.

## Adding a project

1. Add an entry to `src/features/projects/projects.ts`. With a `highlights` list and no folder of
   its own, the project automatically gets a page at `/projects/<id>` from the shared layout.
2. Put its preview images in `public/projects/<id>/preview-light.png` and `preview-dark.png`.
3. For a project with a live demo or its own design, add `src/features/projects/<id>/` and a
   route at `src/app/projects/<id>/page.tsx`.
4. Run `npm run lint`, `npm test` and `npm run build`, then check the page in both themes and on
   a phone-sized window.

## Adding journal photos

1. Add the file names to `scripts/prepare-journal-photos.mjs` and run it on the folder of
   originals. It resizes the photos and removes location and camera data.
2. Add each photo to `journal-data.ts` with the size the script printed and a real description.
3. `npm test` fails if a listed photo is missing or its size does not match.

## Tests

`npm test` runs the files in `tests/` with Node's built-in test runner. Logic worth testing is
kept in plain `.ts` files that do not import through `@/`, so the tests can load them directly.

## Old addresses

`/projects/ethiotunes` redirects to `/projects/zempled`, and `/api/ethiotunes/preview` uses the
same handler as `/api/zempled/preview`. The old resume PDF address redirects in `next.config.ts`.

## Generated files

`.next`, `node_modules`, `next-env.d.ts` and TypeScript build info are generated; do not commit
them. `.env.local` holds secrets and is ignored; `.env.example` shows which values are needed.

## Keeping it maintainable

Prefer clear ownership, readable TypeScript and plain control flow over clever abstractions.
Share code only for a real shared responsibility, and add a dependency only when it earns its
upkeep. Comments explain reasons, not what the code already says. These preferences are also
recorded in `AGENTS.md`.
